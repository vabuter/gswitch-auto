# Три дизайна автоматического режима

## design:mvp

### approach_name

Space-only dictionary auto-correct piggybacking on performConversion (minimal-risk weekend MVP)
### one_paragraph_pitch

Форк gswitch v0.8.0 с одним новым файлом (~260 строк) и ~150 строками точечных правок: на нажатие Пробела демон берёт последнее слово из уже существующего буфера сканкодов, рендерит его в обеих загруженных XKB-раскладках через статическую таблицу evdev→XKB (48 записей), и если слово ≥4 букв НЕ есть в словаре активной раскладки, но ЕСТЬ в словаре другой (две встроенные Bloom-таблицы из punto-rs, MIT, 2.2 МБ, без n-грамм и без «ИИ» в горячем пути), то через ~120 мс паузы (отмена, если пользователь продолжил печатать) вызывает тот же самый performConversion(ActionConvertWord), который сегодня срабатывает по двойному Shift: он сам стирает слово с пробелом, переключает раскладку с подтверждением через gsettings mru-sources, перепечатывает и взводит одношаговый undo (повторный двойной Shift откатывает автоисправление). Активная раскладка читается тем же gsettings-ридером, что уже используется для подтверждения переключения, и только в тот момент, когда исправление вообще возможно (для правильно набранных словарных слов процесс не спавнится). Всё остальное — grab клавиатуры, мышь, исключения по приложениям, n-граммы, трей-чекбокс, X11/KDE — осознанно отложено; режим выключен по умолчанию и работает только на GNOME Wayland с ровно двумя xkb-раскладками.

ПОТОК ДАННЫХ: evdev (reader goroutine, input_reader.go, O_RDONLY, без grab) → eventChan(256)+overflow (switcher.go:447, 1095-1131) → main goroutine processKeyEvent → Push → [хук autoObserve] → … → maybeFireAuto (main goroutine) → LastWordEvents → renderWord×2 → Bloom×2-4 → (gsettings get mru-sources, только если исправление возможно) → emitConversion → uinput (vKeyboard, свой UID в blacklist switcher.go:430-432) → GNOME → приложение.

ТРЕДИНГ/ЛАТЕНТНОСТЬ: всё решение — на главной горутине, без новых горутин/таймеров: рендер+Bloom — микросекунды на каждом пробеле; gsettings-спавн (~10 мс, измерено в брифе) — только когда «shown ∉ D_shown && alt ∈ D_alt» хотя бы в одном направлении, т.е. для правильно набранных словарных слов никогда. Момент выстрела: Space-down + holdoff 120 мс, фактически при следующей итерации цикла (Space-up или 100-мс тик) ⇒ 120–220 мс после пробела, при условии что за это время не нажата ни одна текстовая клавиша. Сама коррекция для «ghbdtn ␣» (7 текстовых событий): 2 switch-события + подтверждение ≥50 мс + LayoutSwitchDelay 100 + 14 backspace + 14 replay по Delay=10 мс + 100 мс ≈ 0,55–0,65 с; итого ~0,7–0,9 с от пробела до конца. На время коррекции главная горутина заблокирована, физические события копятся в eventChan и после Flush() (switcher.go:917) частично теряются для буфера (не для приложения) — как и в ручном режиме сегодня.
### detection_method

Только словарь, никаких n-грамм/ML в горячем пути. Шаги: (1) PreFilter на сканкодах: все клавиши слова ∈ {41, 16-27, 30-40, 43-53} (буквенный блок; цифры 2-13, keypad 71-83, 98 и всё прочее → отказ), 4 ≤ число клавиш ≤ 24, ровно один хвостовой пробел (LastWordEvents), ни одного ENTER/KPENTER внутри. (2) Рендер R1 = слово в Layout1, R2 = в Layout2 через LayoutInfo.KeyMap (реальные XKB-таблицы, не хардкод, т.е. ru-«б/ю/ж/э/х/ъ» на сканкодах 51/52/39/40/26/27 учтены). (3) Для направления i→j: кандидат только если R_j целиком состоит из букв алфавита j (для ru→en это автоматически отсекает любые русские слова с б/ю/ж/э/х/ъ — консервативно), R_i (lowercase, ё→е) ∉ exceptions, known_j(R_j) == true И known_i(R_i) == false, где known — Bloom-фильтр языка (порт PR/src/layout.rs:121-145; данные PR/src/layout/ru.bloom из hunspell-ru 0.99g5 после unmunch, en.bloom из /usr/share/dict/words ^[a-z]+$, PR/scripts/build_layout_model.sh:14-20); если R_i содержит не-буквы внутри (например, «foo_bar» в en при наборе на ru) — known_i=false. (4) Направление выбирается по активной раскладке (см. active_layout_source); исправляем только если active==i и условие (3) выполнено для i→j. Правило 1-2-буквенных слов из punto-rs (keymap.rs:79-103), триграммный margin (layout.rs:84-87) и ретипинг предыдущего короткого слова — НЕ входят в MVP (меньше кода, меньше ложных срабатываний, ниже recall на коротких словах). Пороговых параметров два: auto-min-letters (4) и auto-holdoff (120 мс). Опциональный шаг (2 ч): перегенерировать Bloom на 24 бит/слово (FP ≈1e-5 вместо ≈1%) маленьким Go-генератором по рецепту punto-rs (dnf download hunspell-devel + rpm2cpio + unmunch + iconv koi8-r; на хосте hunspell есть, unmunch — нет, /usr/share/hunspell/ru_RU.dic — KOI8-R со 146 269 основами, напрямую как список слов не годится).
### active_layout_source

Та же механика, которой gswitch уже доверяет на GNOME Wayland: `gnomeWaylandLayoutStateReader{env: s.sessionEnv}.CurrentState()` (GS/internal/gswitch/runtime/gnome_wayland_layout_switch.go:20-41) выполняет `gsettings get org.gnome.desktop.input-sources mru-sources`; результат парсится уже существующим `parseGnomeInputSources` (GS/internal/gswitch/runtime/layout.go:187-203) — первый кортеж = активная раскладка — и сравнивается по Name/Variant с `s.layoutConverter.Layout1/Layout2` (switcher.go:272-287 → resolveLayouts 291-318, на хосте sources=[('xkb','us'),('xkb','ru')], per-window=false, mru-sources заполнен). Если строка пуста (до первого переключения после логина), не парсится или не совпадает ни с одной из двух раскладок — автоисправление пропускается (fail-closed). Чтение выполняется НЕ на каждую клавишу и не на каждый пробел, а только в maybeFireAuto и только когда словарные гейты допускают исправление хотя бы в одном направлении, т.е. ≈ только для действительно подозрительных слов; кэша нет, поэтому рассинхронизации при переключении через индикатор в топ-баре или после собственного toggle (switcher.go:859-878 сам опирается на то, что mru-sources меняется после эмитированного аккорда) не возникает. Демон — user-сервис (GS/configs/gswitch.service:1-17), поэтому RunGsettings с nil env — обычный fork/exec (session_env.go:667-690 требует root только при env≠nil). Подписка на IBus GlobalEngineChanged/dconf Notify через godbus — осознанно отложена (новый код, не проверен на GNOME 50).
### safety_measures

- Выключено по умолчанию: auto-correct=false в configs/default.conf и в шаблоне SaveConfigTo; включается явной правкой /etc/gswitch/default.conf + systemctl --user restart gswitch (это же — аварийный выключатель)
- Жёсткие предусловия при старте: только GNOME Wayland (verifyGNOMEWaylandLayoutSwitch, switcher.go:936-945), не degradedMode (switcher.go:163-169, 706-711), layoutConverter загружен ровно для двух раскладок (resolveLayouts, switcher.go:291-318); иначе режим молча остаётся выключенным с записью в лог
- Триггер — только KEY_SPACE, никогда Enter/KPENTER/пунктуация: LastWordEvents требует ровно один хвостовой пробел и текстовую клавишу перед ним, так что Convert() никогда не перепечатает Enter (двойная отправка в чатах) и второй пробел не вызовет повторного исправления того же слова
- Отложенный выстрел с отменой: исправление выполняется только если после Space-down прошло ≥ auto-holdoff (120 мс), Space физически отпущен и за это время не было ни одной текстовой клавиши/Backspace/killer/autorepeat — слова, через которые пользователь «пролетел», оставляются ручному двойному Shift; это главная мера против перемешивания ввода без EVIOCGRAB
- Двойной словарный гейт (alt известно И shown неизвестно) + минимум 4 буквы + только буквенный блок сканкодов + запрет цифр/keypad + требование «все буквы алфавита» для альтернативного рендера + встроенный список исключений (punto-rs exceptions.txt, расширяемый) — 1-3-буквенные слова и любые токены с цифрами/пунктуацией не трогаются никогда
- Ограничитель частоты: не более одного автоисправления в секунду и не во время inConversion (switcher.go:982-991); fail-closed при любой ошибке чтения активной раскладки или рендера
- Undo без новых клавиш: автопуть завершается CompleteConversion(ActionConvertWord) (switcher.go:918), поэтому немедленный двойной Shift откатывает автоисправление через существующий CanUndo (converter.go:613-636); ReverseMode-своп обходится вызовом emitConversion напрямую, чтобы автоисправление не превратилось в ConvertAll
- Текст не мутируется, пока переключение раскладки не подтверждено через mru-sources (switcher.go:872-875 выходит до backspace'ов) — неудачный toggle = ничего не изменилось
- Приватность сохраняется: никакого сетевого кода, словари read-only и встроены в бинарник (go:embed), слова не пишутся на диск, systemd-hardening unit'а (ProtectHome=read-only, RestrictAddressFamilies) не ослабляется; README/SECURITY форка честно переписываются
- Тестируемость без железа: шов fireAuto в Switcher + мок layoutStateReader по образцу gnome_wayland_layout_switch_test.go:10-26 + конструктор &Switcher{config, converter, ...} из switcher_test.go:174-185; регрессионная таблица из PR/tests/data/layout_cases.tsv (2403 строки, MIT), отфильтрованная до en/ru и ≥4 букв, с гейтом «0 ложных исправлений на keep-строках»

### effort_estimate

С интерактивным тестированием пользователем: реалистично один уик-энд. Суббота (4-5 ч совместно): установка Go и upstream-RPM, форк, реализация пунктов 1-6, зелёные go test, первый живой прогон «ghbdtn ␣ → привет». ### expected_accuracy

Прогноз, не измерение (тесты punto-rs не запускались по правилам задачи; у gswitch словаря нет). Для слов ≥4 букв в паре us/ru: recall ориентировочно 85-95% — пропуски там, где правильное слово отсутствует в hunspell-ru/words (сленг, имена, новые термины, формы с ё в словаре через е учтены), плюс все русские слова с б/ю/ж/э/х/ъ при наборе английского на русской раскладке не исправляются (консервативный гейт «все буквы алфавита» для альтернативы); 1-3-буквенные слова и токены с цифрами не исправляются никогда (в punto-rs это ~10% их размеченного набора). Ложные срабатывания: структурно возможны только для НЕсловарного токена активной раскладки, чей рендер в другой раскладке попадает в её словарь; с Bloom punto-rs (10 бит/слово, ~1% ложных «известно») это примерно 1 из 100 несловарных токенов ≥4 букв, причём детерминированно для конкретного токена (один и тот же «systemctl» либо всегда ошибочно «известен», либо никогда) — лечится строкой в exceptions; после перегенерации Bloom на 24 бит/слово остаточный FP ≈1e-5 и остаются только «настоящие» коллизии (английский термин вне words, чей ru-рендер — русское слово, и наоборот) — у punto-rs на 728 keep-словах их 0 с триграммным margin, без margin ожидаю единицы. Без защиты от паролей/терминала (нет информации о фокусе на Wayland) и без сброса буфера по клику мыши — это ограничения, а не точность детектора.
### risks

- Гонка реплея без grab: если пользователь возобновил печать в окне ~0,6 с коррекции (после 120-мс паузы), его клавиши перемешаются с backspace/replay в приложении (input_reader.go:214 O_RDONLY без EVIOCGRAB; GrabAll input_reader.go:399-418 без вызовов; performConversion синхронно на главной горутине switcher.go:823-920). Holdoff снижает частоту, но не исключает; полный фикс (grab + очередь + ре-инжект, как PR/src/daemon.rs:36-99) отложен во 2-ю фазу
- Пароли и терминал: демон не знает окно/назначение поля (org.gnome.Shell.Introspect закрыт allowlist'ом, AT-SPI выключен), поэтому «ghbdtn» в поле пароля или команда в терминале (≥4 букв, не в words, ru-рендер случайно словарный) будут переписаны; единственная защита в MVP — словарный гейт, exceptions и undo
- Устаревший буфер после клика мыши: мыши не открываются (input_reader.go:220 требует KEY_A), BufKillers (types.go:181-185) — только клавиатурные; после клика в другое поле автоисправление может стереть символы не того поля (upstream issue #36). В ручном режиме это редкость, в авто — на каждом подозрительном слове
- Bloom-фильтр punto-rs даёт ~1% детерминированных ложных «известно» (PR/examples/train_layout_model.rs:21, 10 бит/слово) — без перегенерации на ≥20 бит/слово часть несловарных токенов пользователя будет стабильно портиться до внесения в exceptions

- Видимое мерцание 0,6-0,9 с на каждое исправление при Delay=10/LayoutSwitchDelay=100 (config.go:57-58); снижение задержек апстрим считает рискованным (комментарий switcher.go:855-857), punto-rs работает на 1 мс — нужно измерять на GNOME 50 + IBus 1.5.34
- Трей сотрёт auto-correct при сохранении, если забыть pass-through (WriteConfigFromArgsTo config.go:336-405 и trayConfigWriteArgs settings_window.go:1327-1340 знают фиксированный список ключей) — включено в work items, но это скрытый источник «режим сам выключился»
- Сопровождение форка: апстрим публично закрыл автоисправление как not planned (#12, #31), релизы приходят одним squash-коммитом (CONTRIBUTING.md:7-17), PR не мержатся; каждый релиз — ручной ребейз хука в switcher.go и config.go; шанс апстрима ≈0

## design:accuracy

### approach_name

Margin-gated dictionary+trigram corrector: bit-exact Go port of the punto-rs detector, calibrated on a held-out eval set, with undo-learned exceptions, an IBus-driven layout tracker and grab/replay around gswitch's existing conversion path
### one_paragraph_pitch

Keep gswitch's whole erase→switch→retype machinery untouched (performConversion at switcher.go:823-920 already erases the last word plus its trailing Space and retypes it) and add exactly three things: (1) a way to turn the scancode buffer into text in both layouts (a 47-entry evdev→XKB-keyname table on top of the LayoutInfo.KeyMap gswitch already parses from /usr/share/X11/xkb/symbols), (2) a decision engine that is a bit-exact Go port of punto-rs's detector — per-language letter-trigram cost tables (36 KB ru, 20 KB en) plus Bloom-filter dictionaries (1.7 MB ru, 444 KB en), gated by the rule "the other-layout rendering must be a dictionary word, the on-screen one must not, and the trigram margin must exceed 1 bit/char" — which on punto-rs's held-out set gives 0 false fixes on 360 must-not-touch words and 194/205 (94.6%) recall for the us+ru pair, and (3) an event-driven active-layout tracker fed by IBus GlobalEngineChanged. Accuracy-first additions over punto-rs: a length-scaled total-likelihood threshold, case-shape vetoes for identifiers/acronyms, a conservative "cancel if anything else is typed" scheduler, an exceptions list that grows automatically from the user's undos, and a Go eval harness that ports punto-rs's 2403-row labelled set and adds a personal Russian corpus so thresholds are tuned on dev and reported on test. Everything is offline, pure Go, microsecond-latency, and honours gswitch's no-network security model; the "AI" is a statistical model, not an LLM, by design.

### detection_method

DECISION RULE (per Space press, word = buffered scancodes + shift flags; everything case-folded, ё→е as in PR/src/layout.rs:105-111):
Stage 0 candidate filter (PR/src/layout.rs:196-210): skip if the on-screen rendering contains a digit, if the other-layout rendering has a non-letter inside the word (digits, `_`, `.`), or if it has fewer than auto-min-letters=3 letters; edge punctuation is stripped. Skip if the buffer range contains ENTER/KPENTER (would re-send Enter) or keypad codes.
Stage 1 exceptions: built-in list (PR/src/layout/exceptions.txt) ∪ user list, matched on the lowercased on-screen word without edge punctuation (layout.rs:283-295).
Stage 2 dictionary gate (layout.rs:186-191): alt_known && !shown_known using Bloom filters (~1% false "known"; a false shown_known only suppresses a fix — safe direction; a false alt_known still has to pass Stage 3).
Stage 3 trigram margin (layout.rs:147-154, :186-191): cost(lang, word) = mean over the n+1 trigrams of `^^word$` of table[(a·N+b)·N+c]/10 bits; fix only if alt_cost ≤ auto-max-alt-cost (6.0) and shown_cost − alt_cost ≥ auto-margin (1.0 bit/char). On-screen words with a non-letter inside get UNREADABLE_COST 25.5 (layout.rs:88-89, :211-215).
Stage 4 (accuracy-first additions, each a tunable evaluated on dev before enabling): (a) total-evidence floor: (shown_cost − alt_cost)·(n+1) ≥ auto-min-total-bits (candidate 8) so 3-letter words need a larger per-char margin than 10-letter words; (b) case-shape veto: skip ALL-CAPS ≥3 letters (acronyms: GTK, TLS) and interior capitals (getValue, iPhone) — CapsLock is not tracked by gswitch (types.go has no 58) so Shift-typed caps are the only caps we can see, which is exactly the identifier/acronym case; (c) language-context prior: if the previous word in the same buffer line was a kept, dictionary-known word of the shown language, raise the margin by auto-context-bonus (candidate +0.5 bit/char) — targets chat slang whose alt rendering happens to be a real word (ин→by, ру→he, tls→ела); needs a sentence-level corpus to validate, so off by default; (d) 2-letter words only via the closed frequency lists (PR/src/layout/keymap.rs:80-94: 29 EN, 41 RU) with the shown-word-not-in-list-and-not-in-dict guard (layout.rs:261-269); 1-letter words never alone, only dragged along before a word being fixed across single spaces (PR/src/engine/auto.rs:13-39) — v1.
Stage 5 learning from undo: when a manual double-Shift undoes an auto fix (CanUndo path, converter.go:613-636), record the shown word in memory; on the K-th undo of the same word (auto-learn-undos, default 2; Punto "offer a rule after N undos", xneur EducationMode) append it to ~/.config/gswitch/auto-exceptions.txt (words the user explicitly rejected — never raw keystrokes; opt-in).

### active_layout_source

Primary (event-driven): the IBus private bus. On this host gnome-shell 50.5 switches xkb sources by calling ibus setEngine (gnome-probe brief: activateInputSource → _ibusManager.setEngine → set_global_engine_async), so ibus-daemon emits org.freedesktop.IBus.GlobalEngineChanged(s engine_name) on /org/freedesktop/IBus, and GetGlobalEngine returns e.g. `xkb:us::eng`. The bus address is NOT on the session bus and the IBUS_ADDRESS env var is empty in the service's environment; the daemon parses ~/.config/ibus/bus/<machine-id>-unix-<display> (line IBUS_ADDRESS=unix:path=...) — SessionEnv already carries Home/RuntimeDir/IBusAddress fields (GS/internal/gswitch/detect/session_env.go:53-71). Implementation with godbus (GS/go.mod:7): dbus.Connect(address) + AddMatchSignal(interface org.freedesktop.IBus, member GlobalEngineChanged); engine name `xkb:<layout>:<variant>:<lang>` is split on ':' and matched against the resolved LayoutSpec pair from resolveLayouts (GS/internal/gswitch/runtime/switcher.go:291-318) → atomic index 0/1 + a change channel used both for the "is the better hypothesis already active" decision and to end the post-switch wait early (replacing the gsettings polling at switcher.go:859-878 / gnome_wayland_layout_switch.go:43-89).
Resync/fallback: `gsettings get org.gnome.desktop.input-sources mru-sources` (existing reader gnome_wayland_layout_switch.go:26-41) parsed with parseGnomeInputSources (layout.go:187-203); first tuple = active (mru-sources is only written on interactive switches and is empty right after login — tray/layout_monitor.go:313 — so `sources`[0] is the cold-start fallback). Used at start, after every own correction (the value is already read on the confirm path), and on a 5 s timer only while the IBus subscription is down.
Hint: when the physical switch chord (config.LayoutSwitchKey, [56,42] = LeftAlt+LeftShift on this host from gsettings switch-input-source=['<Alt>Shift_L'], parsed by GS/internal/gswitch/detect/detect.go:1207-1219 and :1229-1278) is seen in the evdev stream, the tracker marks the state "uncertain" until the next signal/resync; auto never fires while uncertain. The chord is never used as the source of truth (top-bar menu switches and IBus restarts would desync it).
Hard gating at startup: auto-correct is enabled only if the pair is exactly {us, ru} (models exist for en/ru only), `per-window` is false (read once via gsettings; README.md:370-377 already tells users to disable it), the session is GNOME Wayland (shouldVerifyGNOMEWaylandLayoutSwitch, switcher.go:936-945), the IBus connection succeeded, and the daemon is not in degradedMode (switcher.go:706-711). KDE/fcitx5/X11 backends are out of scope for v0.
UNVERIFIED: that GlobalEngineChanged really fires for xkb→xkb switches on this exact setup (no keys could be pressed during probing) and whether it fires inside PASSWORD-purpose fields where gnome-shell sets _disableIBus. First live experiment of the project: `gdbus monitor --address <ibus addr> --dest org.freedesktop.IBus` while pressing Alt+Shift and while focusing a password field.
### safety_measures

- Opt-in: auto-correct=false by default in configs/default.conf and the SaveConfigTo template (GS/internal/gswitch/config/config.go:476-553); the manual double-Shift path is byte-for-byte unchanged when the flag is off.
- Space-only trigger: Enter/KPEnter never trigger and any ENTER inside the word range vetoes the fix, because Enter has already reached the app and Convert's replay range would re-send it (GS/internal/gswitch/runtime/converter.go:517-534, :579-596). Exactly one trailing space; a second space never re-triggers (PR/src/engine/auto.rs:66-67).
- Deferred firing: the fix is armed on Space and executed only when every physical key is released plus 30 ms of silence; any text key, Backspace, killer key or autorepeat before that cancels it (PR/src/engine.rs:194-221, :323-335) — v0 never retypes text the user is still editing.
- EVIOCGRAB with held-key refusal and watchdog: grab all keyboards for the duration of the retype (input_reader.go:399-418), refuse if EVIOCGKEY reports any key down (PR/src/devices.rs:54-63), defer UngrabAll plus a 2 s watchdog so a bug can never leave the keyboard dead; captured input is re-emitted after the fix instead of discarded (do not call Flush at switcher.go:917 on the auto path).
- Precision-first decision rule: dictionary gate (alt must be a known word AND shown must be unknown) before any statistics (PR/src/layout.rs:186-191); min 3 letters; digits anywhere → never; interior non-letters in the alt rendering → never; ALL-CAPS and interior-capital tokens → never; thresholds changed only after re-running the labelled eval set (PR/src/layout/AGENTS.md:3,10).
- One-keystroke undo that also teaches: an auto fix arms the existing CanUndo (converter.go:613-636) with lastAction=ActionConvertWord, so the user's normal double-Shift reverts it while no new text key has been typed (converter.go:177); the K-th undo of the same word appends it to the user exceptions list (opt-in auto-learn, stores rejected words only, never keystrokes).
- Direction safety: fire only when the active-layout tracker is in a certain state (fresh IBus signal or resync), never on chord-parity guesses; hard-disable when the layout pair is not exactly us+ru, when per-window=true, when IBus is unreachable, and in degradedMode (switcher.go:706-711).
- Stale-buffer protection: pointer-button presses reset the buffer (new BTN_* reader path; today mice are never opened, input_reader.go:220); a 30 s idle timeout invalidates the word (PR/config/punto-rs.conf:52); the first key of the word must be younger than that when Space arrives.
- Global pause hotkey (auto-pause-key) and tray toggle that clear the buffer and disable auto until re-enabled — the only per-context control possible on GNOME Wayland without a Shell extension (org.gnome.Shell.Introspect is AccessDenied to ordinary callers per the gnome-probe).
- Bounded blast radius per fix: the backspace count equals the number of buffered text keys in the range (converter.go:558-566) so a wrong fix can only ever touch the last word plus its space; partial fixes are logged (count only, never the word) and the buffer invalidated, as punto-rs does (PR/src/daemon/correct.rs:62-71).
- No network, no keystroke persistence: the model is embedded read-only data, the systemd unit keeps RestrictAddressFamilies=AF_UNIX AF_NETLINK and MemoryDenyWriteExecute (configs/gswitch.service:35-36); the only new writable path is %h/.config/gswitch for the exceptions file and only when auto-learn=true (:25 ProtectHome=read-only otherwise unchanged).
- Session guard (v1): correct only in the active, unlocked logind seat0 session of the same uid (PR/src/session.rs:141-212 pattern) so the daemon never types into a lock screen.

### expected_accuracy

Baseline (v0 = bit-exact port of punto-rs's rule and prebuilt us+ru model), measured on punto-rs's held-out test split for the us+ru pair (counts verified in tests/data/layout_cases.tsv): 0 false fixes on 360 must-not-touch words (100 en_ok, 100 ru_ok, 40 code, 40 terms, 40 translit, 40 short_ok) and 194/205 ≈ 94.6% recall on ≥3-letter wrong-layout words (PR/README.md:29-35; the regression tests assert 0 false fixes over all ≥360 keep rows and recall floors, PR/src/layout/tests.rs:52-75). 2-letter words only via closed lists (≈41 short_wrong rows), 1-letter words never alone. Bloom false-"known" ≈1% (10 bits/word, 7 hashes) mostly costs recall, not precision.

Expected in the user's real use: precision is dominated by the dictionary gate and will not be 100% — the residual false-positive classes are chat slang/abbreviations whose other-layout rendering is a genuine word (the shape of exceptions.txt: ин→by, ру→he, tls→ела, jq→од), nicknames and project names, and code identifiers typed into chat; each costs one visible flicker plus one undo keystroke and, with auto-learn, disappears after K undos. Honest target after 1-2 weeks of exceptions convergence: ≤1 unwanted fix per 1,000 typed words (measured by undo rate), recall ≥90% for ≥4-letter words and ≥80% for 3-letter words (the Stage-4 total-evidence floor trades some 3-letter recall for precision). Misses are silent and free: the user falls back to double-Shift.

What accuracy cannot fix: words terminated by Enter (chat) are never auto-corrected on Linux (Enter already delivered); text in password fields, terminals and IDEs gets the same treatment as prose unless the optional Shell extension or pause key is used; the one-backspace-per-key assumption breaks under IBus preedit/autocomplete and produces garbage the detector cannot foresee; CapsLock state is unknown. Decision latency is < 50 µs; the visible correction takes 200-600 ms depending on delays, during which (with grab) the user's keystrokes are queued and replayed, not lost.
### risks

- IBus signal unverified: the whole event-driven tracker rests on gnome-shell 50 emitting GlobalEngineChanged for xkb→xkb switches and on the private-bus address being parseable from ~/.config/ibus/bus/* under the systemd user service; if it fails, the fallback is a gsettings process spawn per word (10-30 ms, nondeterministic after top-bar switches) and direction errors become possible — a direction error converts a correctly typed word into garbage with full confidence.
- Grab/queue/replay is new, untested code in the keystroke path: a bug or crash between GrabAll and UngrabAll leaves the keyboard dead until the watchdog fires; a replayed key-up for a key the compositor saw pressed can cause stuck autorepeat (why punto-rs refuses to grab with keys held); hotkeys like Ctrl+C are delayed by up to one correction.
- Interleaving without grab (auto-grab=false or refused grab): the ~0.2-0.6 s retype races the user's next word; events arriving mid-switch are dropped by GNOME (switcher.go:855-857), and the existing Flush at :917 races the reader goroutine on the same O_NONBLOCK fds (input_reader.go:357, :386) so buffer and screen can diverge and compound across words.
- Lowering gswitch's 10 ms per-event delay toward punto-rs's 1 ms may make GNOME/IBus drop replayed keys; the safe value for GNOME 50 + IBus 1.5.34 must be measured live, and a too-low value silently corrupts corrections.
- No focus/password awareness on GNOME Wayland: org.gnome.Shell.Introspect is AccessDenied to ordinary callers, AT-SPI is disabled, so a password that looks like a wrong-layout word (e.g. a Russian word typed as Latin) would be rewritten and its structure replayed through uinput; the pause hotkey and the optional Shell extension are mitigations, not guarantees.
- Stale buffer after mouse-driven focus changes until the pointer reader lands (today mice are never opened, input_reader.go:220; README's claim is unimplemented, upstream issue #36): an auto fix can backspace characters in a different field.
- Enter-terminated words are structurally unfixable with passive evdev (Enter already delivered; replay would re-send it); chat users will see the uncorrected word sent, which is the single most common Punto use case.
- False positives on the user's own vocabulary (slang, nicknames, project names, tool names like dnf/jq/tls) until the exceptions list converges; the context prior needs sentence-level eval data that does not exist yet; the personal corpus is private text and must be handled only on the user's machine.

- Security-model drift: injecting keystrokes without an explicit user trigger widens the damage of any bug; writing rejected words to ~/.config requires relaxing ProtectHome=read-only; both must be documented honestly in the fork's README/SECURITY instead of inheriting upstream's 'manual and deterministic' claims.
- Build/CI friction: Go and GTK dev packages are absent on the host, the tray needs cgo, golangci-lint enforces funlen 150/gocognit 45/nestif 5 with no per-file exemptions for new files (.golangci.yml:101-116) — fine for a personal fork but adds friction to keeping upstream's CI green.

## design:ux

### approach_name

Quiet Auto: a Caramba-style conservative auto-corrector for a gswitch fork (Space-triggered, grab-protected retype, one-Backspace undo that learns, GNOME Shell focus/purpose extension for exclusions, pause hotkey, sound feedback)
### one_paragraph_pitch

Keep gswitch's proven passive-evdev + uinput replay core (already verified on Fedora 44 / GNOME 50 / Wayland, README.md:103-107) and add an opt-in, default-off automatic mode designed around one rule: a wrong correction must cost the user at most one keystroke, and a correct one must cost nothing. The daemon fires only on the Space after a word, only when an offline trigram+dictionary scorer (ported from punto-rs, measured at 0 false fixes / ~95% recall on a 2403-row labelled set) is confident, and only after all keys are released; it grabs the keyboards for the ~150-400 ms retype so nothing the user keeps typing interleaves (captured keys are replayed afterwards, never lost), plays a short sound, and opens a 1.5 s undo window in which a single Backspace (or the existing double-Shift) restores the original text, flips the layout back and remembers the word as an exception (session-only on first undo, persisted on second). A ~150-line GNOME Shell extension publishes the focused app, wm_class, text-field purpose (PASSWORD/TERMINAL) and current input source over D-Bus, giving the daemon per-app exclusions, password/terminal suppression, buffer reset on focus change (fixing the stale-buffer-after-click bug) and a push feed of the active layout; without the extension the mode fails closed by default. A Pause/Break hotkey, tray pause ("15 min / 1 h / 4 h") and "Don't correct «…»" complete the Caramba-like UX. Everything stays local, no network, no keystroke persistence beyond explicitly undone words, and the patch is isolated (new files + ~60 hook lines in switcher.go/converter.go) so it can be rebased over upstream's squashed releases. This is a permanent fork: upstream closed the request twice as not-planned and positions gswitch as "manual and deterministic" (README.md:8-10, 35-36).

### detection_method

Offline, bit-exact Go port of punto-rs's detector (PR/src/layout.rs, ~300 lines, MIT): (1) render the buffered scancodes as text in the active ("shown") and the other ("alt") layout using gswitch's own XKB tables (so punctuation keys that are letters in ru, e.g. ',' -> 'б', are handled by the real map, not a hard-coded row); (2) candidate filter: >= 3 letters (MIN_LETTERS, layout.rs:81-83), no digit anywhere, no non-letter inside the alt rendering, edge punctuation stripped, 'ё' folded to 'е', case-insensitive (CapsLock is not tracked, types.go has no 58); (3) per-language letter-trigram cost in bits/symbol over '^^word$' (u8 tables, -log2 p x 10; 27^3 + 33^3 bytes) and Bloom-filter dictionary membership (10 bits/word, 7 FNV-1a probes, ~1% false 'known'); (4) decision exactly as layout.rs:186-191: alt_known && !shown_known && alt_cost <= 6.0 && shown_cost - alt_cost >= 1.0 bit/symbol; (5) 2-letter words only through the closed frequency lists (keymap.rs:79-103), 1-letter words never alone, only dragged along with a following corrected word ('F jy' -> 'А он', auto.rs:13-39); (6) exceptions: built-in 20 (PR/src/layout/exceptions.txt) + the user's learned list (from undo) + tray additions, checked on the lowercased shown word before scoring. UX-first additions on top: an optional context bias (auto-context-bias) that raises the required margin when the previous word on the line is a known word of the shown language (reduces 'git'/'jq'-style flips inside Russian prose; enabled only if the ported eval shows no recall loss); a hard 'never' list for scancode patterns that are shell-ish (interior '/', '-', '=', digits). Models: ru from the installed hunspell-ru 0.99g5 (BSD-3-Clause-Modification; /usr/share/hunspell/ru_RU.dic 1,969,349 B) expanded with unmunch, en from /usr/share/dict/words filtered ^[a-z]+$ (public domain), built with PR/scripts/build_layout_model.sh's recipe; only Bloom filters and trigram tables are shipped (~2.2 MB embedded), never word lists; the Ukrainian model is left out of the MIT fork (MPL-1.1 + CC BY-SA sources). 'AI' here deliberately means this statistical model: an LLM cannot sit in the on-Space path (latency budget ~1 ms, and the project promises no network code, README.md:83 and SECURITY.md:24-25; the unit restricts sockets to AF_UNIX/AF_NETLINK and sets MemoryDenyWriteExecute, gswitch.service:35-36). The only sane LLM role is an offline, opt-in helper outside the daemon that reviews the user's undo log to propose exceptions, which is out of scope for the MVP.
### active_layout_source

Three-tier push feed, with the daemon refusing to auto-correct whenever the state is unknown. Tier 1 (preferred, requires the extension): the GNOME Shell extension forwards InputSourceManager 'current-source-changed' (DUMP:4829-4833) as part of its Changed signal (source id like 'xkb:ru'), which is authoritative for the focused field and would also work under per-window mode. Tier 2 (no extension): IBus private bus via godbus: read the address line from ~/.config/ibus/bus/<machine-id>-unix-wayland-0 (present on the box; IBUS_ADDRESS is empty in the session env, so sessionEnv.Home from session_env.go:53-71 is used to find the file), call org.freedesktop.IBus.GetGlobalEngine at start (returns 'xkb:us::eng' here) and subscribe to GlobalEngineChanged(s). gnome-shell calls _ibusManager.setEngine() on every activateInputSource (DUMP:43590-43603 per the probe), so this fires for xkb<->xkb switches; the engine name's second field maps onto the resolved pair (switcher.go:291-318). Caveat: inside PASSWORD fields gnome-shell sets _disableIBus (DUMP:43749-43760) and may not re-emit engine changes, which is harmless because auto is suppressed there and the tracker resyncs on the next focus change. Tier 3 (fallback/resync): the existing gsettings mru-sources reader (gnome_wayland_layout_switch.go:26-41; 'current' is deprecated and ignored) parsed with parseGnomeInputSources (layout.go:187-203), read at startup, after every own correction and every 10 s; it is written only for interactive switches, which includes keybinding switches. Local parity on top: flip when the user's LSKeys chord (switcher.go:193; [56,42] = <Alt>Shift_L on this machine) is seen in the evdev stream and after each confirmed own toggle; any disagreement with a push signal re-syncs to the signal. The same Changed channel replaces the 50 ms gsettings polling loop for switch confirmation. Startup refuses to enable auto mode when org.gnome.desktop.input-sources per-window is true (it is false on the box) or when the resolved pair is not exactly two xkb layouts with models available (us+ru), logging the reason and showing it in the tray.
### safety_measures

- Default off: auto-correct=false in the packaged config; enabling it in the tray shows a one-time explanation of the undo gesture and the pause key.
- Space-only trigger: never on Enter (already delivered to the app and replayed by Convert's range, converter.go:517-534 + :579-596, which would double-submit in chats/terminals) and never on punctuation; a second Space never re-triggers.
- Conservative scorer gates: >=3 letters, no digits, alt word must be in the other dictionary AND shown word must not be in its own, >=1 bit/symbol margin, exceptions checked first, 1-2 letter words only via closed lists; thresholds change only after re-running the ported labelled set with 0 false fixes on keep classes.
- Fire only when every key on every device is released + 30 ms, and only after EVIOCGKEY confirms nothing is physically down; otherwise skip silently (no retry storm, no stuck keys).
- Grab for the retype only (EVIOCGRAB on the already-open fds, input_reader.go:399-408), captured keystrokes are replayed afterwards instead of dropped, a 1 s watchdog and defer paths force UngrabAll, and a daemon crash releases the grab automatically because EVIOCGRAB dies with the fd.
- Synthetic keys are emitted only after the layout switch is confirmed by a push signal (extension/IBus) or the mru-sources fallback, so gnome-shell's mid-switch drops (switcher.go:855-857) cannot garble the replay; on confirmation failure the fix is abandoned before any Backspace is sent, exactly as today (switcher.go:872-875).
- One-keystroke undo within auto-undo-window (1500 ms) via Backspace (held/auto-repeat Backspace is treated as normal deletion, not undo) or the existing double-Shift; undo restores the original scancodes and the trailing space, flips the layout back and records the word as an exception (session-only first, persisted on the second undo of the same word).
- Esc is deliberately NOT an undo key: it reaches the app before the daemon sees it and closes dialogs / leaves vim insert mode; Backspace's app-side effect (one deleted character) is predictable and compensated.
- Per-field suppression: PASSWORD and TERMINAL content purposes from the Shell extension (Main.inputMethod.contentPurpose, DUMP:4834-4836) plus a wm_class/app-id exclusion list with terminals and password managers pre-filled; fail-closed when the extension is unreachable (auto-require-focus=true).
- Buffer cleared and pending cancelled on every focus change signalled by the extension (also covers mouse clicks, which the daemon cannot see because pointer devices are never opened, input_reader.go:220, and the udev rule grants keyboards only, 70-gswitch.rules:7).
- Lexical guards when running without the extension: shell-command-looking lines, tokens with '/', '--', '=', digits or interior punctuation, and space-less mixed-case lines are never corrected.
- Pause/Break hotkey (configurable), tray Pause and Pause-for 15 min / 1 h / 4 h, automatic pause while the screen is locked (org.gnome.ScreenSaver ActiveChanged) and a 30 s idle buffer timeout.
- Auto mode is force-disabled in degradedMode (switcher.go:706-711), when the active layout is unknown, when per-window input sources are enabled, or when the layout pair is not us+ru with models present; the state is visible in the tray.
- Privacy posture kept: no network code, models embedded read-only, keystrokes stay in memory; the only new on-disk data is the exception list of words the user explicitly reverted, documented in SECURITY.md, and the extension exposes focus metadata only (no text).
- Tray feedback is quiet by default: a short freedesktop 'message' sound on fix/undo (distinct ids), no banner unless auto-feedback=toast; sounds are rate-limited.

### risks

- Grab-and-replay is the riskiest new code: a bug can leave the keyboard grabbed or a synthetic key stuck until the watchdog fires; modifier chords typed during the ~200 ms grab are delayed; XKB-level stuck modifiers are possible if a release is mis-sequenced. Mitigated by the held-key check, watchdog, defer paths and the fact that fd close releases EVIOCGRAB, but it needs live soak testing.
- Timing on GNOME 50/IBus is unmeasured: the fork wants 3 ms per event instead of upstream's 10 ms and a signal-ended 60 ms switch wait; if mutter/IBus drops or reorders uinput events at that pace the replay garbles text. Must be calibrated on the box with --debug before freezing defaults.
- GlobalEngineChanged firing for xkb<->xkb switches on this exact setup is inferred from the gnome-shell JS (activateInputSource -> setEngine) and the probe's GetGlobalEngine result, not observed live; if it does not fire, Tier 2 degrades to the 10 s mru-sources resync and auto mode will pause often. The extension's current-source-changed tier avoids this but adds the extension dependency.
- The Shell extension is a second component that breaks on GNOME major updates, is disabled by Shell after crashes, and exposes focus metadata on the session bus; without it the mode fails closed by default, so the user has to maintain it.
- Content purpose (PASSWORD/TERMINAL) is toolkit-dependent on Wayland: Chromium/Electron/Firefox/XWayland apps likely report NORMAL, so password fields in browsers are not reliably detected; a password that renders as a plausible Russian word could be retyped and its structure leaked through uinput. The wm_class list, lexical guards, pause and one-key undo are the only defences there.
- False positives on personal vocabulary (slang, logins, tool names, transliteration, names) are guaranteed initially; the design turns them into one Backspace each plus learning, but a user who finds even that annoying will switch auto off, which is acceptable (manual double-Shift keeps working).
- Enter-terminated words cannot be corrected with passive evdev (the Enter has already been delivered), so chat messages whose last word is wrong go out uncorrected; fixing this would require a permanent grab-and-proxy architecture, which is a different, much riskier project.
- Backspace-as-undo within 1.5 s changes the meaning of Backspace right after a correction (a user who wanted to replace the space with a comma gets an undo instead); the short window, the repeat rule and the double-Shift alternative limit but do not remove the surprise.
- Upstream will not take this: the author closed #12 and #31 as not planned and documents the product as manual; every upstream release is one squashed commit touching switcher.go/settings_window.go, so each rebase is manual conflict resolution. Bus factor is 1 on both sides.
- Persisting the exception list writes typed words to ~/.config and needs ReadWritePaths in the hardened unit; it slightly weakens the 'keystrokes never touch the disk' story and must be documented honestly.
- Scorer licensing/maintenance: embedded models derived from hunspell-ru require 'modified version' marking under its BSD-style licence; the Ukrainian model is excluded from the MIT fork; the eval set must be extended with the user's own Russian chat/terminal corpus to tune the context bias without losing recall.
- Stale buffer when the extension is absent: mouse clicks and touchpad taps are invisible to the daemon (pointer devices are not opened and not covered by the udev rule), so an auto fix after a click can backspace into another field; the lexical fallback does not cover this, only the extension's focus signal does.
