# Автокоррекция раскладки на базе gswitch: оценка выполнимости

## 1. Вердикт

Форк gswitch с автоматическим режимом выполним, но это постоянный хард-форк на недели работы, а не «флажок за выходные»: апстрим дважды закрыл такой запрос как not planned (#12, #31), а демону не хватает трёх входов: активной раскладки, символов (в буфере только скан-коды) и фокуса окна. Вариант A (gswitch как есть, двойной Shift) работает сегодня и проверен автором именно на Fedora 44 / GNOME 50 / Wayland. «ИИ» здесь означает локальную статистику (словарь + триграммы); LLM в горячем пути исключена.

## 2. На что опереться в gswitch (v0.8.0, MIT, Go)

| Готово | Где (`internal/gswitch/`) |
|---|---|
| Пассивное чтение evdev с hotplug, буфер скан-кодов со Space/Enter и состоянием Shift | `runtime/converter.go:104-183` |
| Поиск границ последнего слова с хвостовым пробелом | `runtime/converter.go:517-534` |
| Стирание, переключение, перепечатка через uinput, подтверждение смены раскладки на GNOME Wayland | `runtime/switcher.go:823-920` |
| Разбор XKB-таблиц обеих раскладок при старте | `runtime/layout.go:381-495` |
| Одношаговый undo (повтор триггера) | `runtime/converter.go:613-636` |
| Детект хоткея GNOME (у вас `<Alt>Shift_L`) | `detect/detect.go:1099-1169` |
| Конфиг, трей, RPM-упаковка, godbus уже в `go.mod` | `config/config.go`, `.goreleaser.yml` |

Проверено: обещанный в README сброс буфера по клику мыши в коде отсутствует (открываются только клавиатуры, `runtime/input_reader.go:220`).

## 3. Препятствия на GNOME Wayland и решения

| Проблема | Проверенный факт | Решение |
|---|---|---|
| Активная раскладка неизвестна | Демон хранит скан-коды и слепо шлёт toggle; `gsettings get mru-sources` читается лишь для подтверждения | Подписка на IBus: `GetGlobalEngine` + сигнал `GlobalEngineChanged` на приватной шине (адрес в `~/.config/ibus/bus/*`); сигнал подтверждён на вашей системе. `mru-sources` только как ресинк. Увидели аккорд Alt+Shift в потоке: состояние «неизвестно», не исправлять |
| Нет символов | Таблицы evdev → XKB-имя нет, нужно ~48 записей (X-keycode минус 8); CapsLock и AltGr не отслеживаются | Рендер через уже загруженные `KeyMap`, оценка без учёта регистра |
| Пароли, терминал, фокус | Мыши не читаются, окно на Wayland неизвестно, `org.gnome.Shell.Introspect` закрыт allowlist'ом | Единственный путь: мини-расширение GNOME Shell (wm_class + purpose PASSWORD/TERMINAL). Без него: клавиша паузы, лексические фильтры, undo |
| Гонка при быстром наборе | Grab нет (`input_reader.go:214`, `GrabAll` без вызовов), перепечатка ~0,5-0,7 с синхронно; ваши клавиши перемешаются с backspace | Этап 0: стрелять только после отпускания Space + 120 мс тишины, отмена при любой клавише. Этап 1: EVIOCGRAB с проверкой зажатых клавиш, очередью и ре-инжектом |
| Enter | Уже доставлен приложению; реплей переслал бы его повторно | Триггер только по Space, никогда по Enter |

Опровергнутые утверждения черновиков, на которые я не опираюсь:
- «`performConversion` переиспользуется как есть, undo бесплатен, хук локален». Нет: нужен обход ReverseMode-свопа (`switcher.go:824-831`), обработка хвостового Shift в диапазоне, хук до `Push` (K_UP/K_REPEAT туда не попадают), отказ от `Flush`. Реально 250-400 строк правок в существующих файлах.
- «Существующего ридера `mru-sources` достаточно как источника раскладки». Нет: ключ пишется только при интерактивных переключениях, на хосте порядок оказывался устаревшим.
- «Grab + очередь переносятся из punto-rs один в один». Нет: держать grab до key-up, сторожевой таймер, отказ при зажатой клавише; объём вдвое больше оценки.
- «Цифры punto-rs (0 ложных / 360, 194/205) воспроизведутся». Это самоотчёт автора, здесь не воспроизводился; `unmunch` для пересборки словаря на хосте нет.

## 4. Рекомендуемый дизайн и план

Победитель: дизайн «accuracy» (порт детектора punto-rs + IBus-трекер + grab/replay), привитый осторожностью «mvp» (сначала без grab, консервативный порог) и двумя элементами «ux» (клавиша паузы, расширение Shell как опция).

| Этап | Содержание | LOC с тестами | Время (я пишу, вы тестируете) |
|---|---|---|---|
| 0. Прототип | Триггер по Space, словарный гейт + триграммный margin, IBus-трекер с ресинком, флаг `auto-correct`, undo двойным Shift, holdoff без grab, минимум 4 буквы, лимит 1 фикс/с, Pause/Break, фильтры (цифры, `/`, `-`, `=`) | 1200-1500 | 1-2 недели, 3-5 живых сессий |
| 1. Ежедневное использование | EVIOCGRAB + очередь + ре-инжект, пониженные задержки (измерить на GNOME 50!), исключения из undo, сброс по мыши, чекбокс в трее и 11 локалей | +2500-3000 | +4-6 недель, короткие сессии почти ежедневно |
| 2. Опция | Расширение GNOME Shell: фокус, PASSWORD/TERMINAL, per-app исключения | ~150 JS + 150 Go | +1-2 недели |

Предусловия, которых сейчас нет: Go ≥ 1.25.5, установка upstream RPM ради udev-правила uaccess (вы не в группе input), для трея gtk3-devel и libX11-devel. Сопровождение: ~1 ч ребейза на каждый squash-релиз апстрима.

## 5. Про «ИИ»

- Имеет смысл: офлайн-модель punto-rs (MIT). Триграммные таблицы по буквам (36 КБ ru, 20 КБ en) + Bloom-словари (~2,2 МБ), правило «альтернатива в словаре И показанное слово нет И margin ≥ 1 бит/символ». Решение за микросекунды, без сети. Словари hunspell ru/en на машине уже стоят.
- Не имеет смысла: LLM на каждое слово. Латентность ≥ 300 мс против бюджета в миллисекунды, а security-модель gswitch («no network», `RestrictAddressFamilies` в unit) и статус демона кейлоггер-класса делают отправку нажатий наружу неприемлемой. Локальная нейросеть: тяжёлые зависимости ради того же результата.
- Где LLM полезна: вне демона, офлайн. Разметка личного корпуса для оценки, добыча исключений из журнала отмен, написание кода и тестов форка.

## 6. Сравнение

| Критерий | A: gswitch + двойной Shift | B: форк с авто-режимом |
|---|---|---|
| Усилия | Установить RPM, 10 минут | 1,5-5 тыс. строк, 6-10 недель с живым тестированием |
| Ложные срабатывания | Невозможны | Неизбежны в первые недели (сленг, логины, команды); пароли и терминал без расширения не защищены |
| Поддержка и обновления | Автор, релизы в RPM | Вы и я; ребейз на каждый релиз, апстрим не примет |
| Время до результата | Сегодня | Прототип 1-2 недели, зрелость 2-3 месяца |
| Риск порчи текста | Только по вашей команде | Гонка реплея, устаревший буфер после клика, неверное направление |

## 7. С чего начать

1. Неделя с вариантом A: поставить upstream RPM (это же даёт udev и polkit для форка), пожить с двойным Shift, отметить, где он раздражает.
2. Параллельно эксперимент на 10 минут: `gdbus monitor` на адресе из `~/.config/ibus/bus/*` при нажатии Alt+Shift и в поле пароля. Если `GlobalEngineChanged` приходит, трекер подтверждён.
3. Затем этап 0 с консервативным порогом: минимум 4 буквы, только Space, выключено по умолчанию.

Что нужно от вас: установить Go и RPM (root), 20-30 минут в день на тесты с `--debug` и присылку логов, согласие на триггер только по Space (слова перед Enter в чатах исправляться не будут), по желанию небольшой личный корпус текстов для оценки и решение, готовы ли вы держать расширение GNOME Shell.
